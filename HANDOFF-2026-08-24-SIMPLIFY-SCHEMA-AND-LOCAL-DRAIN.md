## 1. Simplify the JSON the model must emit

The stored packet can stay `2.0.0` if the controller hydrates identity, enums, UUIDs, and search receipts. The change is to **what GLM is asked to produce**. If hydration cannot satisfy the apply contract, bump the packet to `2.1.0` and the prompt bundle past `pre-research-v3-stateless-1`. Do not silently change packet semantics.

Prefer filling defaults and recording Exa calls in the controller over asking the model to restate them.

### Targeted cuts

**Taxonomy.** This is the first-stage killer. GLM already emits domain strings and loose labels. Accept that.

- Keep one `primary` category code.
- `secondary` becomes zero to three category **codes**, not `{ category_code, confidence, rationale }` objects.
- Drop `alternative`.
- `domains` becomes one to six **domain codes**. Controller can attach default confidence.
- One short `rationale` for the whole classification.
- Keep `difficulty`, `content_form`, `evidence_level`, and `lifecycle_stages`, but coerce common near-misses (`talks` → `talk`, `intro` → `introductory`, `ops` → `operations`) before Zod. Unknown values fall back to a documented default rather than dead-lettering the run.

**Transcript analysis.** Keep summary, takeaways, concepts, demonstrations, quantitative claims, limitations, prerequisites, and learning outcomes. Relax minimum string lengths so a shorter but valid summary is accepted. Sections may be omitted or capped at a few titles. Evidence anchors stay, but the **controller assigns UUIDs**. The model returns excerpts and `supports` text only.

**Web context.** Keep resources and entities. They are the ranking/discovery surface.

- Do not require the model to emit `searches`. Record actual Exa `web_search` tool calls in the controller.
- Drop `verified_results` from the model object. Verification is a later, thinner stage or a controller stamp.
- Allow empty `publisher` / `canonical_url`.
- Cap resources and entities at a small number (about 8 each).

**Organization research.** This is the second-stage killer.

- One optional featured organization: `name`, `canonical_url`, `primary_domain_code`.
- Optional `parent_name` and `speaker_employer_name`.
- A short candidate name list, not twenty full candidate payloads.
- `featured_implementation` becomes optional thin text (`name`, `url`) or null. Do not require the nested ownership object from the model.
- `searches` again come from the controller’s Exa receipts.
- `review_required` stays, but only when identity is genuinely missing or conflicting.

**Source verification.** Consolidate. Either merge the useful fields into web context or keep a tiny stage: URL, `verified|likely|uncertain|rejected`, one-line rationale. Drop the duplicated `verified_results` blob and the per-entity authority-tier object.

**Curriculum.** Keep roles, recommended level, lesson placement, lab/challenge one-liners, and a few challenge seeds. Drop fields already present on transcript analysis (prerequisites, outcomes, related category copies) or copy them in the controller.

**Organization profile.** Do not make GLM re-solve the whole graph. Assemble it from organization research + verified URLs. Soften the “primary org must have two to six authoritative sources” model-time rule: if Exa found fewer, mark `review_required` and still complete the packet. That is a concession. Ranking can down-weight thin org evidence; it cannot use a packet that never applied.

**Ingestion intent.** Stay deterministic. No model call.

### Concessions we are explicitly making

- Defaulted confidence and some enums beat a dead-lettered video.
- A thinner org graph with `review_required` beats a perfect graph that never writes.
- Controller-owned search receipts beat asking GLM to reconstruct the Exa trace.
- Controller-owned evidence UUIDs beat invented IDs that fail cross-file checks.
- We will not ask GLM to emit identity fields the controller already knows (`run_id`, `video_id`, `transcript_sha256`, `research_as_of`, `schema_version`).

### What we will not cut

- Primary category
- Domain codes
- Transcript substance (summary / takeaways / concepts / claims)
- Entities and first-party URLs
- Exa usage on web/org stages (the search is free; use the budget)
- A completable organization record, even if thin
- Technology families
- Deterministic apply

## 2. Make automatic Cron ticks finish work instead of burning the queue

These controller bugs must be fixed before any automatic or local drain. They are independent of the schema cuts and should land first if the work is split.

1. **Classify real failures as retryable.** Treat `STAGE_STRUCTURED_OUTPUT_INVALID`, `STAGE_JSON_NOT_FOUND`, `AbortError`, `Delay was aborted`, and `CONTROLLER_INVOCATION_BUDGET_EXHAUSTED` as retryable, with a bounded attempt cap. Today they become `STAGE_TERMINAL` on attempt 1.

2. **Stop the cascade.** If an earlier required stage is `dead_letter` or missing its artifacts, do not claim later stages on that run. Park or fail the run. `STAGE_INPUT_MISSING_ARTIFACT` is a controller bug, not a video defect.

3. **Do not lease-expire into a tight re-claim loop** on the same video after a schema-terminal first stage. One bounded retry series per video, then move on, until the schema is simpler.

4. **Budget aborts are retries, not tombstones.** A 240-second Cron tick that dies mid-stage must leave `retry_wait`, not `dead_letter`.

Schema simplification and these tick fixes together are what “the Cron path will work” means. Do not re-enable production Cron until a local canary has applied one new packet.

## 3. After the fixes, drain remaining eligible videos locally

Queue at pause time: about **830** unprocessed qualified videos, plus the seven videos above that need **new** runs.

Local drain rules:

- Keep production Cron disabled for the whole drain. Never run `pipeline:all` or a local worker while the production schedule is enabled.
- One video at a time until `applied`, `review_required`, or a true terminal error. Then the next video. No interleaving.
- One process loops stages on the same run until no stage remains. That means the current `PRE_RESEARCH_MAX_STAGES_PER_INVOCATION` cap of 1–3 is not enough for a local completion worker; the no-deadline path must keep claiming stages until the run is terminal.
- `--video-id` still cannot bypass qualification.
- Stop the batch on a surprising controller/storage error. Skip only `review_required`.
- Verify the first newly applied packet with `npm run query:pre-research` before continuing the backlog.
- Work from this repository. Source-deploy only if production Cron is later re-enabled.

Suggested first local canary, after the code is in: one of the failed-but-substantive talks (`LzeC1AQ-U5o` or a fresh oldest eligible such as `PAy_GHUAICw`) as a **new** run.
